# 官方示例学习顺序（导航）

> 这份文件只回答三件事：**先看哪个、每个在讲什么、需要什么前置**。不贴代码。
>
> 运行统一走仓库根目录的脚本（已配好 DeepSeek，不用改官方示例）：
>
> ```bash
> uv run run_example.py examples/basic/hello_world.py
> uv run run_example.py --list        # 看脚本自带的简短推荐
> ```
>
> 为什么不直接 `python examples/xxx.py`：那样不会加载 DeepSeek 配置，会去找 OpenAI 的 key。

**图例**

| 标记 | 含义 |
|---|---|
| ✅ | 本仓库已本地适配过，直接能跑 |
| 🟡 | 纯对话类，预计能跑（没被改过，跑不通就小改） |
| 🔑 | 需要 OpenAI 官方 key（用到 Responses API 专有能力，DeepSeek 没有） |
| 🧩 | 需要额外服务或设备（Redis / MongoDB / Docker / 麦克风 / node / Playwright） |

## 一、总体顺序

按阶段推进，**不要跳**。前 3 个阶段是地基，第 4 阶段之后按需深入。

| 阶段 | 目录 | 拿到什么 |
|---|---|---|
| 1 | `basic/` 前 5 个 | 最小闭环：Agent + Runner + 工具 + 流式 |
| 2 | `basic/` 其余 | 单 Agent 的各种能力面 |
| 3 | `agent_patterns/`、`handoffs/` | 多 Agent 的几种组织方式（**重点**） |
| 4 | `memory/` | 会话记忆与持久化 |
| 5 | `mcp/` | 用外部协议接入工具 |
| 6 | `tools/`、`hosted_mcp/` | 托管工具（多数 🔑，当资料读） |
| 7 | `model_providers/` | 怎么换模型厂商 |
| 8 | `customer_service/`、`research_bot/`、`financial_research_agent/` | 完整业务案例 |
| 9 | `sandbox/`、`voice/`、`realtime/` | 重型进阶，最后看或只看代码 |

## 四、阶段 3：多 Agent（重点）

### 3.1 `agent_patterns/` —— 先花 5 分钟读 `agent_patterns/README.md`

官方的模式总览，每种模式一句话。然后按这个顺序读代码：

| 顺序 | 文件 | 模式 |
|---|---|---|
| 1 | `deterministic.py` | 确定性流水线：大纲 → 正文 → 结尾，最直观的编排 |
| 2 | `routing.py` | 用 handoff 把请求路由给专长 agent |
| 3 | `agents_as_tools.py` | agent 当工具调（不接管对话，拿结果就走） |
| 4 | `agents_as_tools_streaming.py` | 同上 + 嵌套事件流 |
| 5 | `agents_as_tools_structured.py` | 同上 + 结构化输入 |
| 6 | `agents_as_tools_conditional.py` | 同上 + 条件触发（含审批） |
| 7 | `parallelization.py` | 并行跑多次再挑最好的 |
| 8 | `llm_as_a_judge.py` | 一个模型生成、另一个模型打分 |
| 9 | `forcing_tool_use.py` | 强制模型必须调某个工具 |
| 10 | `input_guardrails.py` → `output_guardrails.py` → `streaming_guardrails.py` | 护栏三连（含 tripwire 熔断语义） |
| 11 | `human_in_the_loop.py` | 工具审批基础：中断 → 存状态 → 恢复 |
| 12 | `human_in_the_loop_custom_rejection.py` | 拒绝时自定义错误文案 |
| 13 | `human_in_the_loop_stream.py` | 审批 + 流式 |
| 14 | `human_in_the_loop_server.py` | 服务端持有状态、只收决策（含安全说明，值得读注释） |
| 15 | `hosted_multi_agent_beta.py` | 实验性服务端多 agent（🔑） |

> `deterministic` / `routing` / `agents_as_tools` 三个搞懂，多 Agent 就入门了。其余是变体和加固。

### 3.2 `handoffs/` —— handoff 的细节控制

| 顺序 | 文件 | 学到什么 |

| 2 | `message_filter_streaming.py` | 同上，流式版 |

## 六、阶段 5：MCP（`mcp/`）

MCP = 用统一协议接外部工具。每个子目录通常是 `main.py`（入口，读它）+ `server.py`（组件，不用读）。

| 顺序 | 目录 | 学到什么 | 标记 |
|---|---|---|---|
| 1 | `filesystem_example/` | stdio 方式接本地 filesystem server，最典型 | 🧩（需 node/npx） |
| 2 | `tool_filter_example/` | 只放行部分工具 | 🟡 |
| 3 | `get_all_mcp_tools_example/` | 列出 server 提供的全部工具 | 🟡 |
| 4 | `sse_example/` | SSE 传输（先起 `server.py`） | 🟡 |
| 5 | `streamablehttp_example/` | StreamableHTTP 传输（先起 server） | 🟡 |
| 6 | `sse_remote_example/` / `streamable_http_remote_example/` | 连远程 server | 🧩（需外网） |
| 7 | `streamablehttp_custom_client_example/` | 自定义 httpx client（代理/SSL/超时） | 🟡 |
| 8 | `prompt_server/` | 从 MCP server 取 prompt | 🟡 |
| 9 | `manager_example/` | 多 server 的生命周期管理 + FastAPI | 🟡 |
| 10 | `git_example/` | MCP git server | 🧩 |

## 七、阶段 6~9：托管工具、模型接入、完整案例、重型

### 6. 托管工具（`tools/`、`hosted_mcp/`）—— 多数 🔑

这些工具由服务端提供，**DeepSeek 上跑不了**，建议当"能力清单"读，知道 SDK 支持什么即可：

- `tools/`：`web_search.py`、`web_search_filters.py`、`file_search.py`、`code_interpreter.py`、`image_generator.py`、`computer_use.py`、`shell*.py`、`apply_patch.py`、`codex.py`、`programmatic_tool_calling.py`、`tool_search.py`
- `hosted_mcp/`：`simple.py` → `human_in_the_loop.py` → `on_approval.py` → `connectors.py`

> 例外：`hosted_mcp/*` 里关于**审批流**的部分，概念和阶段 3 的 HITL 是一样的，值得对照着看。

## 九、需要额外准备的清单

| 标记 | 具体要什么 |
|---|---|
| 🔑 | `config.env` 换成 OpenAI 官方 key；这些示例用的是 Responses API 专有能力 |
| 🧩 Redis | 本地 Redis（`REDIS_URL`，默认 `redis://localhost:6379`） |
| 🧩 MongoDB | 本地 MongoDB |
| 🧩 Dapr | Dapr sidecar |
| 🧩 node | 装了 node，能用 `npx` |
| 🧩 Ollama | 本地 Ollama 服务 |
| 🧩 音频 | 麦克风/扬声器 + `sounddevice` |
| 🧩 Playwright | `playwright install chromium` |
| 🧩 Docker | 本地 Docker |

> 标记是我按「示例用到的 API 能力」判断的，不是逐个跑过的结论。**跑一次最快**，报错就换下一个，不影响阅读。
