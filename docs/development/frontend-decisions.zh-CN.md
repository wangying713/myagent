# 本项目前端代码具体约定

整理日期：2026-10-14。适用范围：`apps/interfaces/console` 中新增和修改的前端代码。语言依据为 [Google TypeScript 中文规范](google-typescript-guide.zh-CN.md)和 [Google HTML/CSS 中文规范](google-html-css-guide.zh-CN.md)。本文件是本项目的选择与适配，不是 Google 官方要求。

## 1. 规则关系

1. 用户当前明确要求和框架实际语法、入口契约优先。
2. 本文件中明确列出的项目选择与例外优先于对应 Google 通用规则。
3. 其余语言规则参考 Google 中文规范；省略的专项问题查官方原文。
4. 排版以本项目 Biome 配置为准，类型检查以 `tsconfig.json` 为准。

不要为了采用规范批量改造未触及的官方 Demos、生成文件或公共样式。修改旧代码时处理与本次任务直接相关的违规点；新业务代码按本规范编写。

## 2. 与 Google 原文的适配差异

| 事项 | Google 原文 | 本项目选择 |
| --- | --- | --- |
| 默认导出 | TypeScript 代码使用具名导出，禁止默认导出 | Umi 页面、配置、运行时入口和 Mock 保留默认导出；普通业务函数、类型和公共组件优先具名导出 |
| 文件命名 | 小写及下划线约定 | 页面目录沿用现有小写连字符风格，如 `data-management`；组件文件使用 `UserTable.tsx`；页面入口使用 `index.tsx`，普通工具文件使用 `format.ts` 等小写名称 |
| 导入路径 | 同一逻辑项目内建议相对导入 | 页面内部使用相对路径，引用公共代码使用 `@/components`、`@/utils` 等现有别名；Mock 的 Node 加载环境使用实际可解析的相对路径 |
| 类型导入 | 允许 `import type` | 只用于类型的新增导入使用 `import type` |
| 命名空间 | 禁止普通代码使用 `namespace`，外部集成有例外 | 保留工具生成的 `API` 类型命名空间，新业务代码不新增全局命名空间 |
| 简短条件 | 允许单行 `if` 省略花括号 | 新代码的控制流统一保留花括号 |
| 空值比较 | 允许 `value == null` 同时判断两种空值 | 新代码优先明确需要判断 `null`、`undefined` 中的哪一种，使用严格比较 |
| HTML 空标签与属性 | 原生 HTML 的小写属性和空元素规则 | JSX 使用 React 语法，如 `className`、`onClick`、`<img />`，组件使用大驼峰 |
| CSS 排版与命名 | 原生 CSS 的连字符类名、属性排序等 | 原生 CSS 类名遵循用途命名；CSS-in-JS 对象键沿用工具约定；Tailwind 工具类不重命名；排版由 Biome 统一处理 |

框架依据：[Umi 路由文档](https://umijs.org/docs/guides/routes/)、[React 规则](https://react.dev/reference/rules)。现有实现约定以 `console/config`、`console/src` 中实际使用的入口为准。

## 3. 目录与模块职责

| 位置 | 职责 |
| --- | --- |
| `config/` | 路由、构建、代理和默认布局配置 |
| `src/pages/` | 实际页面及其专属资源 |
| `src/pages/demos/` | 已归档的官方示例，保留作参考 |
| `src/components/` | 多个实际页面需要共享的组件 |
| `src/services/` | 当前模板的工具生成服务代码，不直接手改 |
| `src/utils/` | 与页面展示无关的公共工具函数 |
| `src/locales/` | 菜单与页面文案的国际化资源 |
| `mock/`、页面内 `_mock.ts` | 本机演示数据与模拟接口 |

页面专属组件、类型、样式、服务和 Mock 放在页面目录内；出现实际复用需求后再提取到公共目录。

新业务页面不从 `demos` 导入组件、服务或类型。可以参考示例写法，但独立定义实际业务契约。不要为尚不存在的需求建立通用配置系统、组件框架或全局状态层。

路由、菜单名称、权限、组件文件路径和国际化键必须一起维护。

## 4. 命名、导入与类型

- 组件、接口、类型使用大驼峰，函数、变量和属性使用小驼峰。
- 事件处理器采用 `handleSubmit`、`handleDelete` 等用途明确的名称；回调属性可使用 `onSubmit`、`onDelete`。
- 自定义 Hook 使用 `use` 前缀，例如 `useUserList`。
- 默认使用 `const`，避免 `any`、强制非空断言和连续类型断言。
- 组件参数、业务数据、请求参数和响应结构定义明确类型；简单局部值依靠类型推断。
- TypeScript 类型标注不等于运行时验证；外部数据需要的校验不能用 `as` 替代。
- 不创建只有转发作用的多层导出文件，也不复制公共类型到每个页面。

```ts
export interface UserSummary {
  id: string;
  name: string;
  enabled: boolean;
}

export interface UserTableProps {
  users: UserSummary[];
  onDelete: (userId: string) => void;
}
```

以上是示意类型，不表示已经接入用户管理接口。

## 5. React 组件与状态

- 新组件优先使用函数组件。不要在组件函数体中定义另一个组件类型，以免无意重置子组件状态。
- Hook 在组件或自定义 Hook 顶层调用，不放在条件、循环和普通工具函数中。
- 渲染保持纯粹，不在渲染过程中请求接口或修改外部状态。
- 不直接修改 props、state 或 Hook 的返回值；更新集合时创建新值。
- 可从现有数据计算的值直接计算，不为每个派生值再维护一份 state。
- 列表使用稳定的业务标识作为 `key`；可增删、排序的列表不使用数组下标代替标识。
- Effect 只用于与外部系统同步；维护真实依赖，清理监听、订阅和定时器。不要为了避免触发而隐瞒依赖。
- `useMemo`、`useCallback` 根据性能或引用稳定性需求使用，不给每个表达式和函数统一套上。

上述 React 要求属于框架及项目规则，依据 [React 官方规则](https://react.dev/reference/rules)；不是 Google TypeScript 规范中的 React 专项规则。

## 6. 接口、异步与错误

- 组件负责展示和交互；接口路径、请求参数构造及响应解包放在页面服务或明确的公共服务模块中。
- 不在组件内散落多套 `fetch`、Axios 实例或相互不同的鉴权逻辑，沿用项目现有请求入口。
- 明确响应是否包含 `data`、分页信息或业务状态；在服务边界完成必要解包，不靠类型断言掩盖协议差异。
- 服务层保留错误；页面或统一错误处理器负责用户提示，避免同一次失败重复弹出多次提示。
- 页面区分加载、成功、空数据和失败；请求失败不伪装成正常空列表。
- 异步操作必须有明确的成功与失败处理。不会等待的 Promise 也要有错误去向，不能仅用 `void` 掩盖异常。
- 提交期间避免重复提交；查询参数变化时，使用现有查询工具或明确的取消、过期结果机制防止旧响应覆盖新状态。
- 只在与外部 API 接轨且确有需要时兼容非 `Error` 异常值，并说明边界。

当前官方管理台示例继续使用本机 Mock；经用户授权的 Go demo 页面使用已明确的 `/api/agent/*` 后台契约。实际模型请求由 Go 服务执行。其他业务接入前仍需明确后台契约，不预先猜测 API。

## 7. 组件与样式

- 优先使用现有 Ant Design 和 Pro Components，遵循当前依赖版本的组件 API。
- 优先通过组件属性、布局组件和主题 token 完成页面，不给普通业务页面另造一套设计系统。
- 专属样式与页面或组件放在一起，公共样式只处理确实共享的需求。
- 避免全局覆盖组件库内部类名、无理由的 `!important` 和大量重复样式。
- 保持标签语义；按钮、链接和自定义交互需要能通过键盘使用，图标按钮有可理解的名称。
- 页面文案、错误提示、说明和注释使用中文。代码标识符和库名保留惯用写法。

## 8. 自动检查与人工检查

在 `apps/interfaces/console` 目录执行：

```sh
# 对本次修改的文件进行格式检查，按实际路径替换。
npx --no-install biome format src/pages/user/login/index.tsx

# 检查本次修改文件的代码规则。
npx --no-install biome lint src/pages/user/login/index.tsx

# 检查项目类型。
npm run tsc

# 构建前先停止开发服务，构建完成后再重新启动。
npm run build
```

需要修正格式时，对明确的修改文件执行 `biome format --write`；不要用全项目自动修复顺带重写官方示例。`npm run lint` 会执行项目级规则和类型检查；已有示例的告警需要区分是否与本次修改有关，不宣称当前所有规则都已满足。

现有 Biome 关闭了显式 `any`、Effect 完整依赖及部分可访问性规则，并排除了部分生成代码和 Mock。**工具检查通过不等于这些要求已经被自动验证**，评审时仍要检查类型、依赖、权限和交互。当前文档整理不调整这些工具配置。

新增或修改业务行为时，按风险验证关键契约；简单、可逆的文案或默认值调整不要求新增机械重复实现的测试。涉及数据映射、权限、复杂状态和异步竞争时，应有针对性的验证。

实际浏览器中确认相关页面可访问、路由与菜单一致、交互状态正确；涉及登录或权限时分别验证相应角色。新路由还要检查刷新、跳转和返回行为。

## 9. 用大模型开发页面时

给出页面用途、字段含义、允许的操作、状态和已确定的接口契约；缺失的业务信息先确认，不从 Demos 推测真实字段。

要求生成代码遵循本文，优先复用现有组件；任务只修改必要文件。完成后检查引用、类型、接口解包、Effect 依赖、加载与错误状态，并核对实际界面。

后续上线前应移除开发演示账号预填，替换 Mock、明确真实鉴权与权限契约。这些是阶段性工程安排；当前开发环境仍保留已授权的官方演示默认值。
