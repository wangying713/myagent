# Google HTML/CSS 代码规范（中文整理）

核对日期：2026-10-14。原作者：Google。依据：[官方 HTML/CSS 规范](https://google.github.io/styleguide/htmlcssguide.html)。原文采用 [CC BY 3.0 署名许可](https://creativecommons.org/licenses/by/3.0/)，本文件作中文译解、删减、重新组织和示例改写，不是官方中文版本或全文逐句翻译。

原文主要约束原生 HTML、CSS 及相关源文件；不能把 HTML 语法规则直接套用到 React JSX、CSS-in-JS 或 Tailwind。具体适配见[前端具体约定](frontend-decisions.zh-CN.md)。

## 1. 通用规则

- 可用 HTTPS 的图片、脚本、样式等外部资源使用 HTTPS。
- 使用两个空格缩进，不混用制表符和空格。
- 使用 UTF-8，无字节顺序标记；HTML 文档声明 `<meta charset="utf-8">`。
- 原生 HTML 标签和属性名、CSS 选择器和属性通常使用小写；字符串和内容按实际需要书写。
- 删除行末空白。
- 注释按需解释用途和设计原因，不要求每处都加注释。
- 待办事项统一使用 `TODO: 具体事项`。

这些源文件规则不要求编译、压缩后的产物保持同样排版。

## 2. HTML 语义与结构

- 使用有效的 HTML，并选择能表达内容含义的标签。
- 点击执行操作使用按钮，跳转到地址使用链接；不要只为了外观选用不合适的元素。
- 图片提供合适的替代文本；纯装饰图片使用空的 `alt`。
- 把结构、样式和行为分开组织，避免把大量呈现逻辑堆在 HTML 中。
- 避免不必要的 `id`；样式优先使用类名，脚本定位可使用 `data-*`。
- 必须使用 `id` 时，Google 要求使用包含连字符的值，减少与浏览器全局命名属性混淆的机会。

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8">
    <title>数据管理</title>
  </head>
  <body>
    <main class="data-manager">
      <h1>数据管理</h1>
      <button type="button">新增记录</button>
    </main>
  </body>
</html>
```

上例保留完整标签，便于阅读；Google 原文允许省略可省略的 HTML 标签，但这是可选项，不是所有项目都必须采用。

## 3. HTML 格式

- HTML 属性值使用双引号。
- 块、列表和表格元素按结构换行，子元素按层级缩进。
- HTML 空元素不使用 XML 风格的尾部斜杠，例如原生 HTML 写 `<img ...>`。
- 在 UTF-8 下直接书写可读字符，避免无必要的实体转义；`<`、`&` 和特殊不可见字符按语法要求处理。
- HTML5 中不必给普通 CSS 样式表和普通 JavaScript 脚本写冗余的 `type` 属性；模块脚本等有实际语义的声明保留。

**React 例外**：JSX 的 `<img />`、属性 `className`、事件 `onClick` 和组件大写命名遵循 React 语法，不能机械改成 HTML 写法。

## 4. CSS 命名与选择器

- 类名表达用途，避免难懂的缩写和仅描述当前颜色的名称。
- 原生 CSS 类名用连字符分隔单词，例如 `.user-table`、`.filter-panel`。
- 名称尽可能简洁，但不能牺牲可理解性。
- 避免不必要的元素限定，例如能使用 `.user-table` 时，不额外写 `div.user-table`。
- 大型或嵌入式项目可使用应用前缀，但前缀是可选项。

```css
.filter-panel {
  display: flex;
  gap: 12px;
  margin-bottom: 16px;
}
```

使用有效的 CSS，避免保留不生效的属性。Google 的语义类名规则针对自行命名的 CSS 类；Tailwind 的工具类和样式库生成的类名不按这个规则重命名。

## 5. CSS 书写与组织

- 项目内声明顺序保持一致；缺少自动排序工具时，可选择按字母顺序排列。这是原文的可选建议，不是强制规则。有浏览器前缀时按原文约定分组。
- 尽可能使用简写属性；应用时要理解其会设置或重置哪些子属性。
- 零值通常不带单位；`0s` 等存在明确语法需要的情况例外。
- 介于 -1 与 1 之间的小数保留前导零，例如 `0.8em`；十六进制颜色在等价且可以缩成三位时使用缩写。
- 避免 `!important`、浏览器探测和 CSS 技巧性补丁；优先寻找更容易维护的实现。
- 每条声明单独一行，以分号结束；冒号后留空格。
- 多个选择器分别换行，规则块之间留空行。
- 原生 CSS 的属性选择器及适用的属性值使用单引号，`url()` 中不加引号；必须使用 `@charset` 时按语法要求使用双引号。不要与 HTML 属性的双引号规则混淆。
- 较大的样式文件用注释按职责分段。

这些排版细节在本项目交给 Biome；CSS-in-JS 的对象键和属性排列以项目样式工具的语法及可读性为准，不声称与原生 CSS 规则完全一致。

## 6. 本项目使用范围

可以直接采用：语义化、可访问性、明确命名、有效样式、按需注释和外部资源 HTTPS。

需要适配：JSX 属性及标签、CSS-in-JS 对象、Tailwind 工具类、主题变量和自动格式化。完整适配说明见[前端具体约定](frontend-decisions.zh-CN.md)。
