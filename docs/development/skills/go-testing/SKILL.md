# Go 测试评审

这是以 Google 规范为依据的中文适配草案，主题参考社区测试技能，未移植其断言库、统一耗时或固定覆盖率要求。来源见[说明](../../sources.zh-CN.md)。

按需查阅[具体规范的测试章节](../../google-go-decisions.zh-CN.md)和[最佳实践的测试章节](../../google-go-best-practices.zh-CN.md)。

## 选择验证目标

先明确被测行为、调用契约和重要失败路径。测试应能发现真实错误，避免只复述实现步骤或锁定不重要的内部结构。

写测试时围绕用户要求的变化；评审时围绕相关改动；排查偶发失败时先复现，再检查时间、随机性、共享状态、网络和后台协程的影响。

## 测试表达

- 使用 `testing` 包；让测试函数明确表达比较条件和失败信息，不默认新增断言框架。
- 多个场景共享逻辑时使用表驱动测试和有意义的子测试名称；行为差异太大时拆开。
- 失败信息说明操作、输入、实际结果、预期结果，保持实际在前、预期在后。
- 后续检查有效时使用 `t.Errorf`；前置条件失败或继续执行无意义时使用 `t.Fatalf`。
- 结构体测试数据使用字段名；复杂结果使用合适的结构比较或差异报告。
- 错误测试关注契约约定的类型或语义；完整文本是契约时，才比对完整字符串。

## 隔离与并发

- 每个测试能够独立运行，不依赖执行顺序，不共享未经同步的可变状态。
- 辅助函数用于准备与清理；通过 `t.Helper()` 把失败定位到调用者。
- 仅在用例与资源确实独立时使用 `t.Parallel()`。
- 涉及协程和共享数据的改动，使用适当的竞态检测；注意取消、等待退出和清理顺序。
- 不从后台协程调用 `t.Fatal` 或 `t.FailNow`，把结果传回测试协程处理。
- 不用任意睡眠掩盖同步问题；使用明确的完成信号和有界等待。
- 集成测试验证相应边界，不要求所有单元测试启动完整基础设施。

## 常用命令

```sh
go test ./...                        # 运行测试
go test -run TestName ./...          # 按名称表达式筛选测试
go test -race ./...                  # 检查竞态
go test -coverprofile=coverage.out ./... # 生成覆盖率数据
go test -bench=. -benchmem ./...     # 运行基准测试并统计分配
```

根据任务选用命令，不把全部命令作为每次修改的必经流程。新 API、模糊测试和基准测试接口必须符合项目工具链版本。

## 结果

用中文说明哪些行为受到验证、哪些重要风险尚未覆盖。覆盖率用于寻找缺口，不当成质量的替代指标，也不擅自设定百分比门槛。
