# 检索、记忆与会话状态

本章已配一个可运行的小 Demo，后面的章节安排用于继续学习和逐步细化。

## 当前可以运行的 Demo

### 先找资料，再回答

程序在两份内置资料里按关键词找片段，把命中的正文和编号交给模型，再让模型依据资料回答。

管理台打开 **Agent Demos → 检索与记忆**，右侧已有请求参数，可以直接发送，也可以先修改。接口为 `POST /api/agent-demos/retrieval`。页面中的原文链接用于核对相关官方资料；项目设计的例子会单独注明。

**怎么看结果：**sources 是实际命中的资料。问笔记本缺页会找到 demo-notebook-001；问完全无关的问题不会调用模型。

这是最小的关键词检索示例，不是向量检索，也不保存长期记忆。资料是数据，不能当作执行指令。

## 学习目标

先找资料再回答，并分清资料、历史与长期记忆。

## 贯穿案例

给一份商品说明，回答保修问题并指出依据；文档里没有的内容明确说明。

## 章节安排

### 1. 最小检索流程

整理资料 → 按问题找相关片段 → 连同来源交给模型 → 回答并给出依据；先理解流程，再考虑向量库。

### 2. 切分与检索质量

认识片段大小、召回数量、关键词和语义检索，区分“没找到”与“回答错”。

### 3. 记忆写入与读取

决定什么值得长期保存，何时更新、过期或删除；不要把所有聊天都当长期事实。

### 4. 隔离与恢复

按用户或会话隔离状态；识别冲突、过期资料和恶意文档指令，保存进度时考虑恢复。

## 练习方向

用一小份固定资料设计“有依据、无依据、资料冲突、恶意指令、不同用户”五类问题。

## 学会的标准

答案能追溯到资料；没依据时说明；历史、检索资料和记忆不会混为一谈。
