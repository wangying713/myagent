# 07：检索、记忆与状态

**状态：后续课程，Go 版本尚未实现。** 当前没有资料检索、embedding、向量库、SQLite 或跨请求会话。第二课只有本次运行内的历史。

## 把相关资料找给模型

RAG 可以从两个普通步骤开始：程序找到相关片段，再把问题与片段放进模型输入。这不等于重新训练，也不必先引入向量数据库。

未来最小练习使用三份虚构产品资料，各片段有固定来源 ID；先实现纯 Go 关键词检索，返回至多两段并限制总长度。提供的问题与资料属于 user 材料，资料中的指令不能变成 system。没有足够依据时应说明，而不是虚构来源。

引用 ID 存在只能证明引用来自给定集合，不能证明每句话忠于资料。关键词未命中也不能证明整个资料库无答案，需要分开评估检索与回答。

## 固定检索与资料 Agent

固定流程由程序先检索再调用模型；资料 Agent 由模型提出搜索词，程序执行只读搜索并回填，模型可以在预算内再次搜索。流程固定时，普通函数即可，不必增加工具循环。

向量检索是后续替换：切块、embedding、索引、召回、排序。切块会影响上下文，向量相似也不证明事实正确。新增模型端点要记录用量与失败，不默认把大量向量写入 trace。

## 三类状态

| 状态 | 内容 | 存放方向 |
| --- | --- | --- |
| 本次运行 | messages、轮次、用量、工具 ID | 显式局部变量，当前已实现 |
| 会话 | 用户历史、未完成任务 | 按会话隔离的业务存储，尚未实现 |
| 长期记忆 | 核验事实、确认偏好 | 有来源、更新时间和删除能力的存储，尚未实现 |

Trace ID 关联一次运行，不是会话 ID。观测正文会脱敏、截断并可能过期，不适合替代业务数据库或任务恢复记录。模型摘要也可能错，保存成长期事实前需要保留来源并允许纠正。

## 后续练习与通过标准

1. 先写不调用模型的检索测试：相关问题、无答案问题、资料含干扰指令，以及伪造来源 ID。
2. 再增加固定检索流程，展示原资料 → 检索片段 → messages → 回答，分别验证检索和忠实度。
3. 持久化阶段验证重启恢复、不同会话隔离、失败不保存半轮、并发版本冲突不会覆盖历史。
4. 断点恢复时保存工具 ID、参数、执行状态与结果；有副作用动作不能在未知状态下重复执行。

通过标准：能定位检索错误、上下文遗漏、过时记忆和回答不忠实；能说明会话隔离仍需要真实身份与访问校验。
