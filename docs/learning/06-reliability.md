## 当前可以运行的 Demo

### 只给一次模型调用，会发生什么

model_calls 只限制本次演示，默认设为 1。模型提出工具调用后，程序执行工具；如果还要请求模型，就会因为次数用完而停止。

管理台打开 **Agent Demos → 失败与执行边界**，右侧已有请求参数，可以直接发送，也可以先修改。接口为 `POST /api/agent-demos/reliability`。页面中的原文链接用于核对相关官方资料；项目设计的例子会单独注明。

**怎么看结果：**达到限制时 HTTP 为 409，code 为 budget_exceeded，execution.completed 为 false；已有 steps 和 stopReason 都会保留。

把 model_calls 改成 2 再试，比较能否完成。服务自身的次数、工具和 token 上限仍然生效；超时与取消沿用公共规则。

## 学习目标

让任务在出错、超时或花费过多时停得下来。

## 贯穿案例

模型一直调用同一个工具，或者工具执行超时。

## 章节安排

### 1. 错误分类

区分用户输入、模型协议、工具业务错误、网络错误与取消；明确谁处理、谁记录。

### 2. 有界执行

设置任务截止时间、模型与工具调用次数、响应大小和用量限制；先讲清软预算的局限。

### 3. 谨慎重试

只重试适合重试的失败，限制次数和间隔；写操作要考虑重复执行的后果。

### 4. 权限与不可信内容

工具白名单、参数校验、读写分离和必要的人工确认；外部资料中的指令不自动获得执行权。

## 练习方向

为无限循环、超时、取消、未知工具和重复写入各写一条处理规则。

## 学会的标准

每条失败路径都有明确结果和停止条件，不会悄悄丢掉已有结果或无限重试。
