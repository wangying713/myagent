# 流式回答与生成模式

本章已配一个可运行的小 Demo，后面的章节安排用于继续学习和逐步细化。

## 当前可以运行的 Demo

### 生成一段，显示一段

Go 持续读取模型返回的文本事件，收到新文字就传给浏览器，不等待整段回答完成。

管理台打开 **Agent Demos → 流式回答**，右侧已有请求参数，可以直接发送，也可以先修改。接口为 `POST /api/agent-demos/stream`。页面中的原文链接用于核对相关官方资料；项目设计的例子会单独注明。

**怎么看结果：**实时回答会逐段增加。最后的 done=true 表示流已结束，还要结合 code 和 execution.completed 判断是否成功。

点击停止会取消后台和模型请求。断线、截断或没有结束事件都不算完整成功；已有文字会保留。

## 学习目标

理解回答怎样分段到达，以及“停止生成”怎样传到后台。

## 贯穿案例

让模型用生活中的例子解释 Go 的 context，观察文字逐段出现。

## 章节安排

### 1. 分段读取与拼接

认识事件边界和结束标志；一段网络数据不一定是一条完整消息。

### 2. 前后端传递

规划模型 → Go → 浏览器的数据通路，区分等待、生成中、完成和中断。

### 3. 取消和保留部分结果

停止后通知后台取消；保留已收到的文字，但不能标成完整成功。

### 4. 拓展：思考与流式工具参数

思考模式和流式是两个维度；工具参数拼接完整并校验之前不能执行。先学文本流式。

## 练习方向

用“正常结束、中途取消、断线、残缺事件”四类样本画状态变化，不急着接真实模型。

## 学会的标准

能解释首段耗时与总耗时，取消后不会继续追加，残缺内容不会被当作成功。
