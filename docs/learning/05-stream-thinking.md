# 05：流式与思考模式

**状态：后续课程，Go 版本尚未实现。** 当前客户端只支持非流式，并显式关闭思考模式；`Stream=true` 会被拒绝。管理台目前在完整响应后展示结果。

## 流式是返回方式

流式让内容分段到达，通常能更早展示首段，但不保证总耗时或 token 更少。若使用 SSE，客户端要解析事件边界、数据与结束标志，而不是将每一行都当正文。

“你”和“好”需要拼成“你好”；工具参数也可能分成 `{"a":` 和 `2,"b":3}`。只有完整重组、结束状态有效且参数通过校验后才允许执行工具。片段数不是 token 用量。

未来实现至少需解决：按候选和工具索引合并增量；限制累计响应大小；处理中断与取消；保留部分内容但标明未完成；用服务端实际 usage 统计。浏览器端若增加 SSE，还要让连接关闭与 Go `context` 取消贯通。

一个实际模型请求仍对应一个模型 span，不逐片段创建 span。可以记录首段耗时和总耗时；它们需要独立定义，当前仅记录总耗时。

## 思考模式是生成模式

思考与非思考决定生成模式，流式与非流式决定返回方式，两者是不同维度。服务端提供的推理文本不能代替事实核验或答案验算。

原课程的比较题可继续保留：“一个两位数，十位比个位大 3，数位和为 11，求这个数。”参考答案为 74。将来比较模式时，保持题目不变，记录最终答案、耗时、token 和失败；更长的文本不能证明更正确。

工具配合思考模式时，需核对所用模型当前要求的完整消息回传规则。当前 `Message.Raw` 保留额外 assistant 字段，为完整回传提供基础，但不代表已经验证了思考工具流程。

## 后续练习与通过标准

1. 先用假 HTTP 服务测试 SSE 分片、空行、结束、工具参数跨片、中断、超大响应与取消，测试不连接模型。
2. 完成 Go 重组与响应契约后，再新增浏览器实时展示，不直接放开现有 `stream` 字段。
3. 分开增加思考模式支持，核对接口协议，再比较固定题的结果和资源。

通过标准：部分文字不算完整成功，残缺参数不会执行，取消能停止后续动作；能分别解释流式与思考模式的作用。
