# 结构化输出与业务校验

本章已配一个可运行的小 Demo，后面的章节安排用于继续学习和逐步细化。

## 当前可以运行的 Demo

### 模型填表，Go 检查

模型把句子整理成 product、quantity 两个 JSON 字段，Go 再检查字段、类型、重复键和数量范围。

管理台打开 **Agent Demos → 结构化输出**，右侧已有请求参数，可以直接发送，也可以先修改。接口为 `POST /api/agent-demos/structured`。页面中的原文链接用于核对相关官方资料；项目设计的例子会单独注明。

**怎么看结果：**成功时 product 为商品名称，quantity 是 1～100 的整数；缺少信息、格式错误或数量越界都会拒绝，并保留模型原回答。

试试“帮我买三本笔记本”“买点笔记本”“买一千本笔记本”。只提取信息，不下单。

## 学习目标

把一句自然语言整理成程序能读取、检查的数据。

## 贯穿案例

“帮我买三本笔记本” → 商品“笔记本”、数量 3；本章只提取信息，不下单。

## 章节安排

### 1. 先约定结果格式

明确字段名、类型、是否必填，以及缺少信息时如何表达。

### 2. 解析与三层检查

依次检查 JSON 能否解析、字段类型是否符合约定、业务值是否合理。

### 3. 让 Go 接住数据

学习结构体、JSON 解码、未知字段、重复字段和缺失值的处理，区别缺失和零值。

### 4. 失败时不要猜

不靠补括号掩盖截断，不把“买点笔记本”猜成某个数量；输出约束仍需应用校验。

## 练习方向

设计正常、数量越界、缺少数量、错误类型、额外字段和残缺 JSON 六类样本。

## 学会的标准

能分清“模型回答了”和“数据可用”；数量限定 1～100 时，1000 必须被拒绝。
