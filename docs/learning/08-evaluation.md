# 08：评估、交付与后续学习

当前提供三课程序契约测试与人工真实验收方法；自动批量质量评估和只读资料助手尚未实现。

## 不只检查“391”

乘法 Agent 的成功至少要检查：工具获准、参数符合问题、实际结果正确、结果按 ID 回填、最终答案一致、调用在预算内。只有文本碰巧正确却没执行工具，不能通过工具课程验收。

业务证据读页面或 API 的 `steps`，观测证据另查 trace。模型运行完成与观测入库是两项验收，不应相互替代。

## 固定用例

保留原课程的四个计算用例，可在管理台工具页签逐个修改问题；当前没有自动评估按钮或脚本。

| 用例 | 实际结果 | 检查重点 |
| --- | --- | --- |
| 17×23 | 391 | 正数、工具参数与回填 |
| 0×25 | 0 | 零不能被当作空结果 |
| -3×8 | -24 | 负数 |
| 12×8 | 96 | 较小整数 |

未来评估程序同时校验参数、实际工具结果和最终答案，记录通过状态、模型/提示词版本、调用数、用量完整性、耗时与 trace ID。保持题目不变比较修改；开放式问题补人工抽查。若使用模型评分，评分请求也要有预算和观测，评分可能存在偏差。

## 离线契约与真实质量

离线假模型测试验证程序会不会正确回填、拒绝非法参数、停止循环和隔离观测故障。它们不证明真实模型总能选对工具。真实请求验证实际协议与默认成功路径，也不覆盖所有输入和生产场景。

可运行命令与人工验收表见 [验收说明](verification.md)。当前流式中断、会话恢复、检索忠实度等能力尚未实现，也没有相应 Go 验收结果。

## 综合项目路线

未来只读资料助手可以按顺序交付：固定检索与依据校验 → 注册只读搜索工具 → 会话持久化 → 结构化结果 → 固定评估集。至少展示一道有答案题、一道无答案题和一道资料含干扰指令的题。

交付应包含问题、实际资料、工具结果、最终答案和 trace，限制查询长度、返回片段数、轮次与时间，不提供任意命令执行。一次只增加一个能力，便于定位回归。

当前已经有 HTTP 服务与取消，但模板登录是 Mock，不能当真实后端权限。生产阶段的身份鉴权、并发限制、限流、持久队列、恢复、部署与回滚要另立需求。

## 什么时候阅读框架

能回答下面的问题，再比较框架封装了什么：

1. 谁构造消息，谁保存历史？
2. 谁读取工具调用，谁真正执行函数？
3. 结果如何按 ID 配对并进入下一轮？
4. 什么条件停止，错误和取消如何传播，预算怎样累计？
5. 怎样关联根 span、模型与工具步骤？
6. 进程退出会丢什么，哪些动作不能重复执行？

当前继续使用 Go 标准库 HTTP 和显式循环；框架、并发工具或多 Agent 应解决具体需求，而不是遮住这些基本机制。
