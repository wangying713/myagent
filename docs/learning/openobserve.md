# 日志、执行记录与链路观测

本章已配一个可运行的小 Demo，后面的章节安排用于继续学习和逐步细化。

## 当前可以运行的 Demo

### 看看这一趟到底做了什么

运行现有的乘法工具任务，返回每次模型和工具调用的输入、输出与耗时。

管理台打开 **Agent Demos → 日志与观测**，右侧已有请求参数，可以直接发送，也可以先修改。接口为 `POST /api/agent-demos/observation`。页面中的原文链接用于核对相关官方资料；项目设计的例子会单独注明。

**怎么看结果：**steps 用来还原过程；最外层 traceID 用于查链路；telemetry_enabled 表示当前服务是否开启观测。

不开启 OpenObserve 也能看到执行记录。开启后仍需到 OpenObserve 按 traceID 核对，不能只凭一个 ID 判断已成功入库。

## 学习目标

能看出一次任务做了什么、慢在哪里、为什么失败。

## 贯穿案例

一次查价加两次计算，查看整体耗时与各步骤的结果。

## 章节安排

### 1. 三种记录各管什么

日志用于诊断，执行记录展示业务过程，trace 连接一次任务的各段调用。

### 2. 关键字段

记录任务、步骤、父子关系、耗时、用量和完成状态；模型调用与工具执行分别辨认。

### 3. 正文与敏感信息

决定是否采集正文，进行脱敏和限长；展示副本不能修改真正的业务数据。

### 4. 接入与核查

以后接入 OpenObserve 时，再核对当前配置与字段；拿到 trace ID 不代表已经成功入库。

## 练习方向

为一个成功任务和一个中途失败任务设计记录表，找出足够定位问题的最少字段。

## 学会的标准

能根据记录还原过程，并区分模型成功、工具成功和整个任务成功。
