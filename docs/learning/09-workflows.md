# 任务拆分与工作流

本章已配一个可运行的小 Demo，后面的章节安排用于继续学习和逐步细化。

## 当前可以运行的 Demo

### 把一件事分成三步

按拆分、检查、汇总的固定顺序请求模型。每一步都携带原需求和前一步实际返回的内容。

管理台打开 **Agent Demos → 工作流**，右侧已有请求参数，可以直接发送，也可以先修改。接口为 `POST /api/agent-demos/workflow`。页面中的原文链接用于核对相关官方资料；项目设计的例子会单独注明。

**怎么看结果：**stages 是已经完成的步骤，execution.steps 是对应模型请求。中途失败会保留前面的结果。

这是固定工作流，没有额外的多个 Agent，也不会替你执行清单里的外部动作。

## 学习目标

判断一个任务需要固定步骤、动态循环，还是只要一次请求。

## 贯穿案例

把一段需求整理成任务清单，再逐项检查是否缺少信息。

## 章节安排

### 1. 先画固定流程

输入整理 → 拆分 → 执行 → 检查 → 汇总；先把每一步的输入输出说清。

### 2. 计划和执行分开看

计划只是建议，执行结果才是事实；失败后决定停止、补充信息还是重新规划。

### 3. 状态与人工接手

记录当前步骤、已完成事项和待确认项；需要用户决定时明确停下来的位置。

### 4. 何时才需要多个 Agent

先检查一个循环能否解决；只有职责与上下文需要分开时才讨论多 Agent，并考虑协调成本。

## 练习方向

给同一任务画一个固定工作流和一个动态循环，说明选择理由与停止条件。

## 学会的标准

不会为了“更像 Agent”增加多层设计，能说明每一步为何存在。
