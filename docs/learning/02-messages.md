# 消息历史与上下文

本章已配一个可运行的小 Demo，后面的章节安排用于继续学习和逐步细化。

## 当前可以运行的 Demo

### 第二次提问为什么记得前面的内容

一次请求内按顺序问两个问题。第二次请求模型时，把第一轮问题和模型实际回答一起带过去。

管理台打开 **Agent Demos → 消息历史**，右侧已有请求参数，可以直接发送，也可以先修改。接口为 `POST /api/agent-demos/messages`。页面中的原文链接用于核对相关官方资料；项目设计的例子会单独注明。

**怎么看结果：**questions 必须正好是两个非空问题。execution.steps 中第二次模型请求应该包含第一轮的真实消息。

这只是本次请求里的对话历史，不会跨请求保存，也不是长期记忆。

## 学习目标

理解模型为什么能接着聊，以及历史由谁保存。

## 贯穿案例

第一轮“我给小猫取名豆包”，第二轮“小猫叫什么”。

## 章节安排

### 1. 完整消息顺序

保存 user 和实际 assistant 回答，下一轮一起发送；不是只发送上次答案。

### 2. 上下文的代价

历史越长，输入通常越大；认识上下文窗口与截断、摘要的取舍。

### 3. 会话隔离

区分一次请求、一段会话和长期记忆；不同用户的历史不能混用。

## 练习方向

写出两轮请求的消息列表，删掉第一轮再比较第二轮还剩哪些信息。

## 学会的标准

能解释“模型记得”的信息来自哪里，并发现错序、丢失和串会话的问题。
