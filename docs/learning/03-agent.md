# 第三课：模型提出调用，程序决定怎么执行

```sh
go run ./apps/interfaces/learning -lesson agent -env-file .env -verify
```

阅读顺序：`MultiplyTool` → `Registry.Dispatch` → `Agent.Run` → 入口组装的观测工具分发器。

## 一次工具循环

1. 程序把乘法工具的名称、说明和参数模式发送给模型。
2. 模型返回 assistant 消息和 `tool_calls`，其中参数是 JSON 字符串。
3. 程序检查调用 ID、已注册工具、JSON 与参数约束，再执行普通 Go 函数。
4. 程序用相同 `tool_call_id` 构造 tool 消息，保留完整 assistant 工具消息并追加结果。
5. 再次调用模型，获得正常结束的文本回答。

一轮可以提出多个工具，程序顺序回填每一个结果。工具定义不是执行授权之外的动态代码：只能调用明确注册的函数，不执行 shell，不把模型文本交给解释器。

典型 17×23 运行是根节点、模型、工具、模型四个 span。轨迹可变化，验收按实际请求和分发次数计算，不硬编码必须有四个。

## 错误与预算

未知工具返回 `unknown_tool`，无效 JSON 返回 `invalid_json`，参数错误返回 `invalid_arguments`。这些失败结果可以回填给模型，模型有机会修正；用户取消会终止整个运行。

工具调用 ID 缺失或重复时整轮拒绝。工具次数不足以执行整轮时，不先执行其中一部分再失败。

默认最多五次模型请求、八次工具分发；达到上限明确报告未完成。token 预算在两次请求之间检查，单次请求仍可能越过预算；缺失用量时，只有请求数和工具数的限制仍能严格执行。

## 小练习

1. 用 `-question "请用工具计算 12 乘以 8"`，查看参数、实际结果和下一轮消息。
2. 把 `AGENT_MAX_MODEL_CALLS` 改为 1，观察工具执行了但最终答案尚未生成的情况，再恢复。
3. 在离线测试中添加非法参数，确认工具没有被执行且错误结果被回填。
4. 仿照乘法工具增加一个具有独立说明与参数校验的本地工具，再注册它，不修改核心循环。

通过标准：能解释工具模式、调用 ID、参数校验、实际执行证据和停止条件；知道“模型说调用了工具”不能替代程序实际执行。
