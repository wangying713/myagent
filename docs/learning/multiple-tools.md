# 工具进阶：多个工具协作

**状态：课程大纲，尚未开发。** 当前只有乘法工具；管理台已展示本节计划，没有查价工具或新的运行接口。本节接着 [03 工具调用与手写 Agent 循环](03-agent.md) 学，不要求先学流式。

## 这节解决什么问题

之前模型只需要决定是否调用乘法。现在多给它一个工具，看看它怎样选择，以及拿到一个工具的结果后，怎样继续调用另一个工具。继续使用现有循环，不额外引入通用工具框架。

课堂案例：“每盒 17 支笔，买 4 盒，一共几支、多少钱？”

计划提供一份本地示例价格表：每盒笔 23 元。模型可先调用查价工具，再通过乘法算出 68 支、92 元。这里仅查询示例数据和计算，不创建订单或付款。实际调用可以是一轮多个，也可以分多轮，不把固定调用顺序当作唯一正确答案。

## 一步步学

1. **增加查价能力**：准备本地示例价格表，输入商品名称，返回单价；不存在的商品明确返回“未找到”，不让模型编造价格。
2. **说明两个工具的用途**：乘法负责计算，查价负责取数据；每个工具分别声明参数、返回结果，并在 Go 中检查参数。
3. **交给模型选择**：同时提供两个工具描述，沿用现有分发和循环。收到调用后逐个执行，保留完整 assistant，并按调用 ID 回填每个真实结果。
4. **读懂执行记录**：看清查到的单价怎样进入后续乘法参数，以及最终回答是否与工具记录一致。
5. **处理失败与停止**：未知工具、错误参数、未知商品都要有明确结果；继续保留现有取消、调用次数和 token 预算检查。

先用假模型和本地数据验证分发、回填与停止，再接真实模型观察它的选择。新增工具不会自动获得读文件、联网或执行命令的能力。

## 动手练习

| 问题或样本 | 观察重点 |
| --- | --- |
| 用工具计算 17×4 | 是否只使用需要的乘法工具 |
| 查询一盒笔的价格 | 是否从本地数据得到 23 元 |
| 每盒 17 支笔，买 4 盒，一共几支、多少钱 | 查价结果是否用于计算，最终是否为 68 支、92 元 |
| 查询价格表里不存在的商品 | 是否说明未找到，而不是编造价格 |
| 离线构造未知工具、缺失参数或重复调用 ID | 校验是否生效，错误是否按现有契约回填或停止 |
| 降低模型调用额度，或中途取消 | 是否报告未完成，并保留已完成步骤 |

## 学会的标准

- 能说出每个工具做什么，以及这次为什么需要它。
- 能从记录找到工具名称、参数、真实结果和配对 ID。
- 能解释“先查价格，再算总价”如何通过消息回填串起来。
- 失败时能指出在哪一步出错；只有答案文字、没有实际工具记录，不算完成组合工具练习。

后续可结合 [失败、预算与权限](06-reliability.md) 继续练习边界；并发执行、联网查价和真实交易不在本节范围内。
