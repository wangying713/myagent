# 学习代码与课程评审

文档、代码和运行记录应描述同一行为。评审时结合 [开发规范](../development/README.md)，不把历史课程能力当作当前实现。

## 按具体证据检查

| 检查点 | 应能找到的证据 |
| --- | --- |
| 请求与默认参数 | 实际请求包含配置模型、完整消息、非流式和关闭思考 |
| 历史 | 第二次请求保存第一轮真实 assistant，原始额外字段不会丢失 |
| 工具 | 描述与分发一致，参数严格校验，未知函数不执行 |
| 协议配对 | 每个调用有唯一 ID 和对应 tool 结果，多工具完整回填 |
| 响应完成 | HTTP 状态、角色、正文、结束原因与用量分别验证 |
| 停止 | 模型/工具/已知 token 预算和 context 取消能明确中止 |
| 失败 | 不伪造答案，已完成步骤可见，错误不会暴露凭据 |
| 观测 | 实际请求和工具各一个子 span，脱敏副本不修改业务数据，上报故障不覆盖结果 |
| 生命周期 | 共享连接与 provider 由服务关闭，单次状态不串请求 |
| 页面 | 取消与新请求不相互覆盖，步骤来自真实 API，登录 Mock 与后端权限分清 |
| 文档 | 链接、命令、字段与 Go 代码一致，未实现课程明确标注 |

## 当前教学边界

累计 token 是软预算，未知 usage 不作零消耗；观测使用内存队列，入库需要另查；每次点击独立，没有持久会话；前端登录为模板演示；没有生产身份、限流或恢复机制。

评审失败场景用离线假模型和内存 exporter，默认不调用真实服务。当前检查命令与真实验收范围见 [验收说明](verification.md)。旧问题及处理经过见 [Python 历史评审](history/python-review.md)，不能作为当前 Go 代码已满足全部契约的证明。
